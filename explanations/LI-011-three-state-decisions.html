The Mental Model Invariant

PostgreSQL, pgvector, and Redis are not three interchangeable “memory” databases. They represent three distinct workload questions across two physical runtimes.

Storage Rule: Choose boundaries by query shape, durability requirement, and data lifetime—not by whatever tool already exists in the stack.

Runtime Error / Consequence
FATAL: remaining connection slots are reserved for non-replication superuser connections (WAL lock contention, autovacuum choke)

Key Questions Resolved

  • Is pgvector a 3rd database? No. It lives directly inside PostgreSQL's process memory.
  • Is Redis always ephemeral? No. Persistence (AOF/RDB) is optional; "may expire" defines the workload.
  • Does this need a benchmark? No. It establishes architecture boundary heuristics.
