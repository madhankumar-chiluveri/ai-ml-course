# Visual Brand System

Build recognition through a stable system, then vary the evidence treatment by topic. Use roughly 80% fixed brand language and 20% archetype-specific accents; do not imitate a creator's signature look.

## Stable foundation

| Token | Value | Use |
|---|---|---|
| Ink | `#0B1220` | Primary dark background and headings |
| Paper | `#F8FAFC` | Light background and text on Ink |
| Slate | `#94A3B8` | Secondary labels and metadata |
| Signal | `#38BDF8` | Core brand accent, links, and key path |
| Success | `#22C55E` | Verified or improved state only |
| Warning | `#F59E0B` | Constraint or unresolved risk only |
| Failure | `#F43F5E` | Failed state or critical evidence only |

- Use one modern sans-serif family with three weights; fall back to Inter, Arial, or system sans.
- Use a consistent 12-column grid, generous margins, left alignment, and a small footer containing the series label and author/name mark.
- Use solid shapes, simple line icons, and consistent 2 px connectors. Avoid stock “AI brain,” robot, neon circuit, and generic gradient imagery.
- Make the evidence—not decoration—the dominant visual object.

## Archetype variation

| Archetype | Accent / motif | Primary evidence object |
|---|---|---|
| AI Lab Notebook | Signal + Success; graph-paper ticks | Plot, result table, equation, or comparison |
| Production Blueprint | Signal; blueprint grid and directional paths | Architecture, boundary, or decision diagram |
| Production AI Failure File | Failure + Warning; trace markers | Error excerpt, failed output, causal chain, or before/after |
| Product Proof | Signal + Success; device or terminal frame | Real screenshot, demo frame, or observable state change |
| Engineering Field Notes | Paper-forward with restrained Warning accent | One artifact, annotated note, or no visual |
| Technical Analysis Brief | Signal plus one product-neutral secondary accent | Change/delta card, sourced comparison, or decision impact |

Accent colors identify meaning, not entire unrelated themes. Do not change typography, grid, footer, icon language, or base palette per topic.

## Information-shape layouts

- **One result:** headline, dominant result/plot, setup strip, limitation footer.
- **Comparison:** two aligned columns with the decision criterion highlighted; avoid false winner language.
- **Architecture:** one reading direction, labeled boundaries, numbered path only when sequence matters.
- **Failure:** visible symptom, causal path, fixed state, and verification marker.
- **Carousel:** cover promises a concrete outcome; one reasoning step per slide; final slide summarizes action and limitation.
- **Video:** show the outcome in the opening seconds, keep cursor/text legible, caption spoken content, and remove dead time.

## Mobile and accessibility gate

- Design for LinkedIn mobile preview; the main claim must be legible without zooming.
- Keep a single-image card to one idea and roughly 25–45 visible words unless the evidence itself is a table or trace.
- Maintain at least WCAG AA contrast; do not encode state by color alone.
- Use labels, arrows, or patterns with color-coded diagrams.
- Add concise alt text describing the evidence and conclusion, not every decorative detail.
- Never fabricate a screenshot, terminal output, chart, or product UI. Label mockups and illustrative data.

## Quality rejection rules

Reject a visual when it is template-first, repeats post copy as decoration, contains unreadable evidence, implies unsupported certainty, or resembles a named influencer closely enough to be mistaken for imitation.
